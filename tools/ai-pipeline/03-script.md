# ③ 写台词并输出本子 JSON

**输入**：第 ② 步的案件设计稿。
**输出**：完整的本子 JSON 对象（`questions` 先留空，由第 ④ 步补上）。
**目的**：把设计稿写成逐句台词，格式直接能被网页读取。

---

## 提示词

```
你是一名视觉小说编剧。请根据下面的案件设计稿，写出游戏台词，并按指定的 JSON 格式输出。

【角色】
- 灰羽（编号 guide）：引路人，眼镜少女，冷静、话少、偶尔毒舌，热爱推理。
  她的作用是引导玩家注意细节、吐槽可疑的地方，但绝不直接说出答案。
- 旁白（编号 narr）：描述环境和动作，用第二人称“你”指代玩家。
- 其他人物：按设计稿的身份和性格说话，嫌疑人可以说谎，但谎言要能被线索揭穿。

【写作要求】
1. 每句台词不超过 40 个汉字。长句拆成多句。
2. 开场 intro：12–20 句。交代时间地点、案件、传说或悬念，最后由灰羽介绍嫌疑人并引导玩家开始调查。
3. 推理前 deduce：2–4 句，灰羽提醒玩家用证据说话。
4. 真相 truth：12–20 句。按时间顺序还原案件，解释每条关键线索和误导线索，最后灰羽说一两句点评。
5. 每个调查行动 4–7 句。获得线索的那一句要写得具体，让玩家读到后能明白线索内容。
6. 灰羽的台词可以加 pose 字段切换立绘：idle（平常）、thinking（思考）、investigate（调查/发现）、unimpressed（不以为然）。
7. 不要使用 emoji。引号用中文引号“”。
8. 语言要有画面感和节奏，但不要堆砌形容词。

【输出格式】
只输出一个 JSON 对象，不要输出其他文字，不要使用 Markdown 代码块以外的说明。结构如下：

{
  "id": "英文短名_01",
  "title": "作品名",
  "subtitle": "四字副标题 | 第一案",
  "source": "改编自 作者《作品名》（公有领域）",
  "difficulty": "入门 或 进阶",
  "cover": "两位数字编号",
  "aiNote": "AI 辅助拆解原著并生成台词与线索树，人工校对证据链",
  "summary": "案件概要，100–200 字",
  "victim": "被害人",
  "speakers": {
    "narr": { "name": "", "voice": null },
    "guide": { "name": "灰羽", "voice": "guide" },
    "人物编号": { "name": "人物名", "voice": "high 或 mid 或 low" }
  },
  "characters": [
    { "id": "c1", "name": "", "title": "", "motive": "", "alibi": "", "aliases": ["其他译名、简称、英文名"] }
  ],
  "clues": [
    { "id": "k1", "name": "6 字以内", "text": "一句话" }
  ],
  "scenes": {
    "intro": [ { "s": "narr", "t": "台词" }, { "s": "guide", "t": "台词", "pose": "thinking" } ],
    "deduce": [ ... ],
    "truth": [ ... ]
  },
  "actions": [
    { "id": "a1", "type": "talk 或 search", "label": "按钮文字", "clueIds": ["k1"], "lines": [ ... ] }
  ],
  "questions": [],
  "solution": "真相一句话总结，80 字以内"
}

注意：
- speakers 的键（如 "henry"）用英文小写，台词里的 "s" 必须是 speakers 里存在的键。
- 每条线索必须至少出现在一个行动的 clueIds 里。
- 嫌疑人的 aliases 要包含常见的其他中文译名和英文名，困难模式判定答案时会用到。

---
案件设计稿如下：
{{第 ② 步输出}}
```

---

## 使用提示

- 输出很长时，可以分两次：先要“intro + deduce + truth”，再要“actions”，最后自己拼起来。
- 拿到 JSON 后，先粘贴进 `validate.html` 检查一次格式，再进入第 ④ 步。
