# AI 改编流水线

> 制作方针、原则和提示词速查索引见同目录下的 `PROMPTS_AND_GUIDELINES.md`；本文件只讲流程和数据格式。

把一部推理小说改编成本网页可以直接运行的“本子”（`data.js` 里的一个对象）。

整个流程分两个阶段：

- **第 ⓪ 步：文学分析与关卡分级**（`00-literature-analysis.md`）。判断一部作品能做成哪几关、各是短篇 / 中篇 / 长篇，产出作品分析报告和关卡策划，存放在项目根目录的 `archive/`。
- **第 ①–⑤ 步：把一个关卡写成本子**。每步一个提示词，上一步的输出作为下一步的输入。最后用 `validate.html` 做程序检查，再人工通读一遍。

```
原著文本 ──⓪ 文学分析──> archive/ 里的关卡策划（选定一关）
原著文本 + 关卡策划 ──① 提取素材──> 素材表 ──② 设计案件──> 案件设计 ──③ 写台词──> 场景与行动
                                                         └──④ 出题──> 推理题
③+④ 合并 ──⑤ AI 复查 + validate.html 程序检查 + 人工通读──> 粘贴进 data.js
```

报告里可以概括为：**AI 生成 → 程序校验 → 人工审核**。

## 文件

| 文件 | 用途 |
|---|---|
| `00-literature-analysis.md` | ⓪ 文学作品分析与关卡分级（短篇 / 中篇 / 长篇），产出 `archive/` 中的报告与策划 |
| `01-extract.md` | ① 从原著中提取人物、时间线、线索。只记录事实，不做改编 |
| `02-design.md` | ② 设计案件：选哪段情节、谁是嫌疑人、证据链、误导线索 |
| `03-script.md` | ③ 写开场、调查行动、真相揭晓的逐句台词，并输出完整本子 JSON |
| `04-questions.md` | ④ 出推理题：选择题选项 + 填空题答案与别名表 |
| `05-review.md` | ⑤ 让 AI 以“挑刺玩家”的角度复查逻辑漏洞 |
| `06-case-package.md` | ⑥ 标准终点：把案件打包成 data.js + 沉浸隐藏知识 + 真相拼图 |
| `validate.html` | 双击打开，粘贴本子 JSON，自动检查格式和证据链，并可试判填空答案 |

## 使用方法

1. **准备原著。** 用英文原著（例如 Project Gutenberg 上的公有领域文本）。现代中文译本的译文本身有版权，不要整段照搬。
   - 原著很长时，按章节分批放进第 ① 步，最后合并素材表。
2. **按顺序运行提示词。** 把每个文件里“提示词”部分整段复制给大模型（推荐长上下文模型），并把 `{{...}}` 占位处替换成上一步的输出。
   - 每一步都先人工看一眼，再进入下一步。早期的错误到后面会被放大。
3. **合并 JSON。** 第 ③ 步输出完整的本子对象，第 ④ 步输出 `questions` 数组，把它替换进第 ③ 步的对象里。
4. **运行第 ⑤ 步**，按 AI 指出的问题修改。
5. **程序检查。** 双击打开 `validate.html`，粘贴 JSON，点“检查”。红色错误必须修，黄色警告视情况处理。
6. **人工通读**，然后把对象粘贴到项目根目录 `data.js` 的 `window.SCRIPTS` 数组里，刷新网页即可游玩。

## 本子数据格式（v2）

完整示例见项目根目录 `data.js` 中的 `hound_01`。

| 字段 | 说明 |
|---|---|
| `id` | 唯一编号，英文加数字，例如 `scarlet_01` |
| `title` / `subtitle` / `source` / `difficulty` / `cover` / `aiNote` | 选关卡片上显示的信息 |
| `summary` | 开场对白结束后显示的案件概要，100–200 字 |
| `victim` | 被害人 |
| `speakers` | 说话人表。键是台词里 `s` 用的编号；`name` 为空表示旁白；`voice` 决定对白音效的音高：`guide`（灰羽）/ `high` / `mid` / `low` / `null`（旁白，使用中性音高） |
| `characters` | 嫌疑人：`id`（c1、c2…）、`name`、`title`、`motive`、`alibi`、`aliases`（其他译名和简称，填空判定会用到） |
| `clues` | 线索：`id`（k1、k2…）、`name`（6 字以内）、`text`（一句话） |
| `scenes.intro` / `scenes.deduce` / `scenes.truth` | 开场、推理前、真相揭晓的台词数组 |
| `actions` | 调查行动：`id`、`type`（`talk` 对话 / `search` 搜证）、`label`、`clueIds`（读完后获得的线索）、`lines`（台词） |
| `questions` | 推理题，见下 |
| `solution` | 真相一句话总结，结局页显示 |

**台词**：`{ "s": "说话人编号", "t": "台词", "pose": "idle|thinking|investigate|unimpressed" }`。`pose` 只对灰羽有效，用来切换左侧立绘。每句建议不超过 40 字，便于逐字显示。

**推理题**：

```json
{
  "id": "q3",
  "prompt": "猎犬为什么会在黑夜里发光？",
  "kind": "clue",
  "choice": { "options": ["k1", "k6", "k3"], "answer": "k6" },
  "fill": {
    "sentence": "凶手在猎犬身上涂了{{0}}，让它看起来像从地狱来的魔犬。",
    "answers": [{ "text": "磷光涂料", "aliases": ["磷光", "磷粉", "荧光涂料"] }]
  },
  "basedOn": ["k6"]
}
```

- `kind` 为 `character` 时选项是嫌疑人编号，为 `clue` 时是线索编号。
- 简单模式用 `choice`，困难模式用 `fill`。`sentence` 可以省略，此时直接对 `prompt` 作答。
- `basedOn` 是推出答案所依据的线索，检查工具会确认这些线索都能在调查中拿到。

> 沉浸模式与真相拼图的字段（`script.coach`、`script.closing`，含 `coach.deductions[].pair` 与 `closing.slots[].requires`）见 `06-case-package.md`；每新增一个案子都要按那里的规范产出。

## 填空判定规则（`judge.js`）

按顺序判断：

1. 去掉空格、标点和符号，全角转半角，英文转小写。
2. 与标准答案或任一别名完全相同 → 正确。
3. 如果是“谁是凶手”类题目，输入里出现了其他嫌疑人的名字 → 错误（防止把所有人名都写上）。
4. 输入中包含标准答案或别名（两个字以上） → 正确，例如“我觉得是斯台普顿”。
5. 与标准答案或三字以上的别名相比，错字不超过限度 → 正确。限度：1–2 字不允许错，3–5 字允许错 1 个，6 字以上允许错约四分之一。
6. 只比限度多错 1 个字 → 判为“很接近”，提示检查错字，不扣机会。

所以**别名表很重要**：同义说法、不同译名、简称都要写进 `aliases`。错字交给第 5 条处理，不需要穷举。
