# 项目方针与提示词汇总

> 给接手这个项目的任何 AI / Agent 看的"怎么做、按什么方向做"。只写方针和可复用的提示词，"现在有什么功能"见根目录 `FEATURES.md`，"做过什么改动"见 `CHANGELOG.md`。

## 0. 项目背景（决定了很多"为什么这样做"）

这是本科生课程「AI创新创业项目」的课程作业：一个纯网页小游戏「谜案重启」，把公有领域悬疑推理文学改编成轻量剧本杀体验，配一个引路人吉祥物"灰羽"。背景信息：

- **开发者基本独立完成**，小组长想法不清晰、推进效率低，开发者选择自己把东西做出来而非争论方向，同时维持表面和谐。
- **硬性目标：课程分数 ≥ 85 分。**
- **课程要求项目要有"由 AI 完成的功能"**——这是目前最大的扣分风险点。现状：AI 的作用主要体现在"离线改编剧本"（`tools/ai-pipeline/`），网页运行时还没有真正调用 AI 的功能。**后续如果要补一个运行时 AI 功能，优先考虑"困难模式下由大模型判定自由作答的开放题，并由灰羽点评"**，这样能现场演示。做之前要和开发者确认（涉及 API key 管理、是否联网调用等新复杂度）。
- **可能的发布渠道**：B 站的 "bilibili toy" 小游戏平台。据此：资源文件（图片、音频）要克制体积；`archive/` 和 `书原文/` 目录含版权材料、调试用原文，**不能随发布物一起上传**。

## 1. 技术方针（硬约束，不要违反）

1. **零依赖、零构建**。不引入任何打包工具、包管理器、框架。所有代码是可以直接用浏览器打开 `index.html` 运行的原生 HTML/CSS/JS。新增功能时问自己："这个能不能用原生 JS 写"——几乎总是可以。
2. **纯前端，没有后端**。所有状态存 `localStorage`（键名见 `FEATURES.md`），没有服务器、没有数据库。
3. **中文为主的产品语言**，面向中文用户；代码注释和变量名用英文（已有代码的风格），面向用户的所有文案用中文。
4. **新增脚本文件要在 `index.html` 里登记 `<script>` 标签**，并注意加载顺序——后加载的文件如果用到前面文件导出的 `window.xxx`，必须排在后面。现有顺序见 `FEATURES.md` 的"文件地图"一节，改动前先确认依赖关系没被打破。
5. **存档兼容性**：改了 `app.js` 里 `save()`/`load()` 涉及的字段结构，必须同时升级 `STORAGE_KEY` 的版本号后缀（如 `murder_restart_save_v3` → `_v4`），避免老用户读到旧存档报错或行为异常。
6. **无障碍与响应式不是可选项**：现有代码大量使用了 `aria-*` 属性、`prefers-reduced-motion` 适配、手机端媒体查询断点。新增 UI 组件要比照现有风格做，不要退步。
7. **本地环境工具路径**（Windows，开发机上的固定路径，不是通用路径）：
   - 可用的 Python（带 Pillow + numpy）：`C:\Users\Dr1zzle\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`（PATH 上的 `python` 是 Windows Store 的占位程序，不能用）。
   - ffmpeg：`C:\Users\Dr1zzle\AppData\Roaming\bilibili\ffmpeg\ffmpeg.exe`。
   - 有 Chrome，可用无头模式（`--headless=new`）截图或跑测试脚本来验证网页功能，不需要用户手动点击确认。

## 2. 游戏设计方针

1. **剧本数据与代码分离**。新增一个案子永远是"在 `data.js` 的 `window.SCRIPTS` 里加一个对象"，不应该为了某个案子的特殊情节去改 `app.js` 的状态机逻辑。如果某个案子的玩法真的需要新的交互方式（比如"时间线排序"），要先评估是否值得给所有案子都加这个通用能力，而不是写一次性代码。
2. **难度分级的推理题设计**：每道题必须同时提供 `choice`（简单模式，选择题）和 `fill`（困难模式，填空题）两种作答方式，共用同一套 `basedOn` 线索依据。不要只做一种。
3. **推理公平性是红线**：
   - 玩家必须能仅凭游戏内出现的线索推出答案，不能要求玩家读过原著。
   - 不能出现"关键证据在揭晓时才突然出现"——原作里如果有这种设计（例如《失窃的信》中警察对信件外观的描述，原文直到结尾才完整揭示给读者），**必须在开场或调查阶段就把它作为可查看的线索交给玩家**，并在策划文档里标注【原创改编】。
   - "谁是凶手"类问题的填空判定要把其他嫌疑人的名字当作禁用词，防止玩家靠"把所有名字都写一遍"蒙对。
4. **引路人灰羽的台词风格**：冷静、话少、偶尔毒舌，热爱推理，不会直接说出答案，只做引导和吐槽。新增台词要延续这个人设，不要写成热情洋溢或插科打诨的风格。
5. **氛围要求**（来自文学改编流水线的设计理念，同样适用于整个项目）：安静、神秘、沉浸、克制、具有文学气息，鼓励玩家专注阅读与思考。**不要为了增加交互而强行加入无意义的探索、战斗或小游戏**；推理体验与故事本身的质量优先于交互数量。

## 3. 文学改编方针（给 `archive/` 和 `tools/ai-pipeline/` 用）

完整的分步提示词在 `tools/ai-pipeline/00-literature-analysis.md` 到 `05-review.md`，这里只总结跨步骤都要遵守的原则：

1. **先分级，再动笔**。拿到一部新作品，先用第 ⓪ 步判断它适合拆成几个关卡、各是短篇（5–10 分钟）/ 中篇（15–20 分钟）/ 长篇（25–35 分钟），产出作品分析报告和关卡策划，再进入 ①–⑤ 步把某一个确定要做的关卡写成 `data.js` 的本子。不要跳步直接写台词。
2. **版权边界**：
   - 优先用公有领域的英文/日文/中文原著原文，**不要整段照搬现代译本的译文**（译文本身有版权，哪怕原作已进入公有领域）。
   - `archive/Literature_Library/<作品>/source.md` 只是内部分析材料，每部作品必须配一份 `copyright_notes.md` 说明版权状态，**这些文件不能随游戏发布**。
3. **尊重原作，但允许标注过的改编**：不能改变核心诡计、关键人物的真实动机，不能制造与原作矛盾的新事实；可以为了游戏性压缩背景、合并情节、补全公平性所需的信息，但必须在策划文档里用【原创改编】明确标出。
4. **时代敏感内容要处理，不要删除历史真实性**：原作中如果带有民族、性别等偏见性的概括描述（例如某部作品里"某国人都如何如何"的刻板说法），删去偏见性的概括，但保留具体的历史称呼；推理依据只能来自具体的物证和行为，不能来自对某个群体的刻板印象。
5. **长文本允许"定向阅读"，但必须如实标注**：超长篇（约 20 万字以上）可以先查网络梗概建立全书框架，再精读关卡实际依赖的原文段落；凡是只依据梗概、没有精读原文核实的内容，必须在分析报告里标「待核对原文」，不能默认当作已核实的事实。
6. **关卡编号一经分配，永不复用或更改**，即使后来判定"不采用"也要保留编号并写明原因。
7. **每次产出关卡策划后，必须回去更新 `archive/Case_Index/master_case_index.md`**（状态列：策划中/已上线/暂不采用），否则下一个接手的人无法知道哪些策划已经变成了真正的本子。

## 4. 协作与交接方针

1. **每次对项目做出实质改动后，在 `CHANGELOG.md` 最上面新增一条**（日期 + 一句话标题，然后列出做了什么、涉及哪些文件）。这是已经在执行的硬性要求，格式照抄现有条目。
2. **这个项目会在多个 AI / Agent 之间辗转**，所以：
   - 不要假设你知道"为什么之前这么做"——先看 `FEATURES.md`、`CHANGELOG.md` 最近几条、`ROADMAP.md`，再动手。
   - 做了会影响后续理解的决策（比如跳过某部作品、推迟某个功能），要在 `ROADMAP.md` 或对应的策划文档里写清楚原因，不要只在对话里口头说明——对话历史不会传递给下一个接手的 Agent。
   - 涉及"这是未来另一个项目的预告，不要据此改动当前项目"这类用户澄清过的方向性决定，要以书面形式落地在文档里（本项目的做法是写一条项目记忆，同时在相关提示词文件开头加"与本项目对齐的说明"小节，见 `00-literature-analysis.md` 的写法可以参考）。
3. **改动前先验证环境里的假设**：如果备忘或文档里提到某个文件路径、某个工具版本，先用工具确认它还存在、还能用，再依赖它——环境可能已经变化。

## 5. 当前方向性决定速查（避免重新讨论已经定好的事）

- 「谜案重启」目前按**纯网页文字游戏**形态推进，**不是像素风游戏**。文学分析提示词里提到的"Mystery Archive / 像素风叙事冒险游戏"是开发者构想中的**未来项目**，不是现在要做的方向，不要因此给当前项目加像素美术或改名。
- `hound_01`（巴斯克维尔的猎犬）未来会定位成"教程关"，目前保持不动，不急着改。
- 《月亮宝石》是缩写本，不是全本，**跳过不做**。
- 《三侠五义》是开发者特意选的"中国风"素材，目标是挑其中最有名/最方便改编的公案做成短篇关卡（而不是整部改编）。
- 《白衣女人》当前提取的原文**译者和出版社不明**，等开发者找到新译本后再处理版权问题；分析报告已基于现有文本完成，可以先用，但发布前要换成确认过来源的译本重写。
