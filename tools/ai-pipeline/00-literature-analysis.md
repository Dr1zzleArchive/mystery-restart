# ⓪ 文学作品分析与关卡分级（Mystery Archive）

**输入**：一部或多部中文 Markdown 格式的悬疑 / 推理 / 犯罪文学原文。
**输出**：作品分析报告、各关卡策划文档、关卡索引更新。
**在流水线中的位置**：在 `01-extract.md` 之前。本步骤决定“这部作品能做成哪几关、各多长”。之后每一个确定要制作的关卡，再分别进入 ①–⑤ 步，生成网页可运行的本子 JSON。

---

## 与本项目对齐的说明（相对于原始提示词的调整）

原始提示词按“像素风叙事冒险游戏”写成。本项目当前是网页原型，因此做了以下对齐。**未列出的部分完全保留原意。**

1. **游戏形态**：当前是网页文字推理游戏（逐字对白 + 调查行动 + 线索背包 + 选择 / 填空推理题），暂不包含像素画面。原提示词中的“场景探索”在网页里对应“调查行动按钮”。
2. **引路人**：所有关卡都有引路人“灰羽”陪同。原作中“叙述者”的作用，如华生式的提问者，可以由灰羽承担。
3. **文件位置**：原提示词建议的 `Mystery_Archive/` 目录，在本项目中放在 `archive/`：
   ```text
   archive/
   ├── Literature_Library/<作品名>/   source.md · story_analysis.md · copyright_notes.md
   ├── Case_Database/Short|Medium|Long/   <编号>_<关卡名>.md
   ├── Case_Index/master_case_index.md
   └── Templates/   story_analysis_template.md · case_design_template.md
   ```
4. **版权**：现代中文译文受版权保护。分析时可以引用原文作为依据，但游戏文本必须重写；`source.md` 不得随游戏公开发布。每部作品都要写 `copyright_notes.md`。
5. **长文本的阅读方式**：超过约 20 万字的长篇，可以先通过网络梗概建立全书结构，再定向精读关卡所依赖的原文段落。报告中必须标注“定向阅读”，凡是只依据梗概的内容，都标为「待核对原文」。不得在只读了梗概的情况下声称完成了全文分析。
6. **公平性改编要显式标注**：如果原作把关键信息藏到最后才揭晓（例如《失窃的信》中局长对信件外观的描述），改编时必须把它提前交给玩家，并在策划中标注【原创改编】。
7. **时代敏感内容**：原作中带有民族、性别等偏见的表述，不得作为推理依据出现在游戏中。保留历史称呼，删去概括性的偏见描述，并在策划的“改编注意事项”中写明处理方式。
8. **与网页本子的衔接**：策划文档中写明“网页本子 id”和“开发状态”；关卡制作完成后，回到 `master_case_index.md` 更新状态。

## 提示词

（以下为开发者提供的原始提示词，第二节与第七节的文件结构按上文第 1、3 条理解。）

当开发者向你提供一部或多部中文 Markdown（.md）格式的经典悬疑、推理或犯罪文学原文时，你需要完整阅读和分析文本，理解故事结构、人物关系、案件逻辑和推理过程，并根据故事内容与适合的体验时长，将原作中的故事转化为可供游戏开发使用的独立关卡策划方案。

你不是简单的小说摘要工具，也不是机械的文本切割工具。你需要从游戏设计角度判断：

- 哪些故事具有独立成关的价值？
- 哪些案件适合制作成短篇体验？
- 哪些案件需要较长的阅读和推理过程？
- 哪些故事必须保持完整，不能随意拆分？
- 哪些情节适合转化为玩家调查、收集证据和逻辑推理？
- 原作中哪些信息必须保留，哪些内容可以在游戏改编时压缩？

最终目标是为 Mystery Archive 建立一个长期、统一、可持续扩展的文学关卡素材库。

### 设计理念

游戏的核心体验：沉浸阅读故事 → 探索案件场景 → 调查人物和物品 → 收集证据与证词 → 理解线索之间的关系 → 独立思考并完成推理 → 揭晓真相。

氛围要求：安静、神秘、沉浸、克制、具有文学气息，鼓励玩家专注阅读与思考。不要设计成单纯的点击式小说，也不要为了增加交互而强行加入无意义的探索、战斗或小游戏。**推理体验与故事本身的质量优先于交互数量。**

### 关卡长度分类标准

长度指玩家实际体验所需的时间（阅读、理解、调查、推理），不能简单根据原作字数判断。以下字数均为初期估算，不是硬性限制；不得为了满足字数要求而强行改编。

| | Short | Medium | Long |
|---|---|---|---|
| 目标时长 | 5–10 分钟 | 15–20 分钟 | 25–35 分钟 |
| 有效游戏文本 | 约 800–1800 字 | 约 2000–4000 字 | 约 4500–8000 字 |
| 场景 | 1 个（可少量补充） | 2–4 个 | 4–7 个 |
| 主要人物 | 2–4 | 3–7 | 5–10 |
| 有效线索 | 3–6 | 6–12 | 10–20 |
| 推理 | 1 个核心谜题、1 次明确判断 | 1–2 个推理节点，至少一次证据关联或证词矛盾 | 2–4 个推理节点，至少一次重要的信息反转或认知修正 |
| 适合的原作 | 独立短篇、单一诡计、简单身份谜题、小型密室、单一证词矛盾 | 多嫌疑人短篇、多场景犯罪、较复杂人物关系、有误导的信息控制 | 多视角叙事、多个关联事件、复杂密室或连续案件、需要逐步拼凑的故事 |

短篇也必须有完整的悬疑体验，不能为了控制长度而删除必要线索、关键人物动机或真相解释。

### 核心分析流程

1. **确认输入与文本完整性**：作品名、作者、年代、原始语言、文件数、章节数；是否有缺失、乱码、重复、截断。文本过长时主动分批读取并记录进度；只有部分章节时标记为「部分文本分析」，不得擅自补全情节。
2. **理解完整故事**：背景、人物、关系、主要事件、真实事件过程、表面呈现的事件、关键线索、作者设置的误导、真相揭晓方式、核心悬疑价值。建立内部的真实事件时间线，区分：实际发生了什么 / 玩家最初知道什么 / 调查中逐步知道什么 / 最终应推断出什么。不能把叙述者的说法直接当作客观事实。
3. **识别可独立改编的故事单元**：合格的关卡应有明确的事件、可理解的背景、明确的调查目标、足够的线索、可推出的结论、相对完整的结局。不要为了增加关卡数量而把完整案件拆成缺乏独立意义的片段。
4. **判断关卡长度**：依据故事实际长度、人物数、场景数、线索数、推理复杂度、必要背景长度、是否有独立完整的推理过程、信息量、是否需要多次调查、能否自然结束。同一故事可以提出不同长度的方案，但必须说明区别，且**不得通过单纯删减关键线索来制作短篇版本**，不同长度的版本必须在逻辑上各自成立。

### 输出格式

- 作品分析报告：按 `archive/Templates/story_analysis_template.md`。
- 每个关卡的策划：按 `archive/Templates/case_design_template.md`。其中 A–G 节为原提示词规定的内容：
  - A. 玩家体验的故事梗概（不泄露真相）
  - B. 完整事件真相
  - C. 主要人物表
  - D. 关键线索表，重要程度分为必要 / 重要 / 补充 / 干扰；干扰线索必须公平
  - E. 推理过程
  - F. 游戏化改编建议
  - G. 预计体验节奏

### 改编原则与限制

1. **尊重原作**：不改变核心诡计、关键人物的真实动机；不制造与原作矛盾的新事实；原创改编内容必须明确标记。
2. **保持推理公平**：不能出现关键证据在揭晓时才突然出现、真相依赖玩家无法获得的信息、人物突然承认此前毫无铺垫的事实、通过隐藏必要信息制造的不公平反转。
3. **控制文本长度**：区分必须保留的核心剧情、可压缩的背景、可转为 NPC 对话的信息、可转为场景交互的信息、可作为补充档案的内容。
4. **不要强行游戏化**：主要依赖语言风格、心理描写或叙述技巧的故事，应明确指出，可建议作为纯叙事关卡、背景档案或暂不采用。
5. **不要擅自增加复杂系统**：优先考虑阅读、选择、点击调查、线索收集、人物对话、证据匹配、时间线排序、逻辑判断；需要复杂自由探索或大型系统才能成立的关卡，单独标注开发成本。

### 持续工作机制

每次收到新作品：

1. 自动识别为新作品，按本流程完整执行，不重新询问格式。
2. 生成独立的作品分析报告和关卡策划文档。
3. 更新 `archive/Case_Index/master_case_index.md`。编号（MA-S-001 / MA-M-001 / MA-L-001）一经分配不得改变。
4. 指出与已有作品相似的案件，但不得因此套用旧作品的案件逻辑。
5. 不确定的事实标注「待核对原文」，不编造解释。
6. 在最后给出本次新增关卡的汇总表。

**我们不是在把小说切成不同长度的文本，而是在把文学中的悬疑与推理体验，转化成不同规模的互动游戏关卡。**
