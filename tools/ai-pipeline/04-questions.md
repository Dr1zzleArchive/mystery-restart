# ④ 出推理题

**输入**：第 ② 步的“推理题”和“证据链”，以及第 ③ 步 JSON 中的 `characters` 和 `clues`。
**输出**：`questions` 数组（JSON），替换进第 ③ 步的本子对象。
**目的**：每道题同时生成简单模式（选择题）和困难模式（填空题）两种形式。

---

## 提示词

```
你是一名推理游戏的出题人。请根据下面的案件信息，生成推理题的 JSON 数组。

【每道题同时有两种形式】
- 简单模式 choice：选择题。
  - kind 为 "character" 时，选项是嫌疑人编号（c1、c2…），通常用于“凶手是谁”。
  - kind 为 "clue" 时，选项是线索编号（k1、k2…），问“哪条线索说明了……”。
  - 选项 3–4 个，只有 1 个正确，干扰项要选“看起来相关但不对”的。
- 困难模式 fill：填空题。
  - sentence：一句陈述句，用 {{0}} 标出要填的空，例如“凶手在猎犬身上涂了{{0}}”。“谁是凶手”这类题可以省略 sentence，直接回答 prompt。
  - answers[0].text：标准答案。必须是 2–6 个字的关键词，不要是一整句话。
  - answers[0].aliases：所有应该判为正确的其他写法。包括：
      · 同义词和近义说法（如“磷光涂料”→“磷光”“磷粉”“荧光涂料”“夜光粉”）；
      · 人名的其他译名、简称、英文名；
      · 更具体或更笼统但仍然正确的说法。
    尽量写全，6–12 个。错别字不用写，程序会自动容错。
  - 不要把“看起来像但实际错误”的说法放进 aliases。

【出题要求】
1. 共 4–6 题，必须覆盖：凶手是谁、作案手法、动机，另外 1–3 题考关键细节。
2. 每道题写 basedOn：推出答案所依据的线索编号（1–3 个）。这些线索必须是玩家在调查中能拿到的。
3. 题目问法要明确，只有一个合理答案。避免“为什么”类的开放问题，困难模式的空只填一个关键词。
4. 题目顺序：从容易到难，“凶手是谁”放第一题。

【输出格式】
只输出 JSON 数组，不要输出其他文字：
[
  {
    "id": "q1",
    "prompt": "凶手是谁？",
    "kind": "character",
    "choice": { "options": ["c1", "c2", "c3", "c4"], "answer": "c4" },
    "fill": { "answers": [{ "text": "标准答案", "aliases": ["别名1", "别名2"] }] },
    "basedOn": ["k6", "k8"]
  },
  {
    "id": "q2",
    "prompt": "……",
    "kind": "clue",
    "choice": { "options": ["k1", "k6", "k3"], "answer": "k6" },
    "fill": { "sentence": "……{{0}}……", "answers": [{ "text": "……", "aliases": [] }] },
    "basedOn": ["k6"]
  }
]

---
嫌疑人与线索（JSON）：
{{第 ③ 步 JSON 中的 characters 和 clues}}

案件设计稿中的证据链与推理题：
{{第 ② 步输出的相关部分}}
```

---

## 使用提示

- 拿到结果后，打开 `validate.html`，在下方“试判答案”里输入几种你能想到的写法（同义词、错字、把所有嫌疑人都写上），看判定是否合理。判错了就补 aliases。
