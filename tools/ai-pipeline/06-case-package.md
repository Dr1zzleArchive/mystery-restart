# ⑥ 案例成品打包（标准流程终点）

> 作用：在 ⓪–⑤ 之后，用**一份标准提示词**把案件一次性整理成网页可直接使用的「三件套」——① 普通/困难模式的 `data.js` 本子、② 沉浸模式的隐藏知识（推理图）、③ 真相拼图数据。以后每新增一本书，只需重复 ⓪ → ⑥，不再每次单独梳理格式。
>
> 想用免费网页 AI 先跑初稿、省 token？见 `tools/web-ai-case-pack/WORKFLOW.md`（两步法：设计稿 → 成品 JSON）。

## 标准流程总览

| 步骤 | 文件 | 输入 | 输出 |
|---|---|---|---|
| ⓪ | `00-literature-analysis.md` | 整本书 | 关卡分级 + 选定要改编的片段 |
| ① | `01-extract.md` | 选定原文片段 | 素材表（人物/线索/时间线/真相） |
| ② | `02-design.md` | 素材表 | 案件设计稿（嫌疑人/线索/证据链） |
| ③ | `03-script.md` | 设计稿 | `script` 本子 JSON（questions 留空） |
| ④ | `04-questions.md` | 设计稿 + script | `questions` 数组 |
| ⑤ | `05-review.md` | ①②③④ | 复查逻辑漏洞 |
| ⑥ | **本文件** | 设计稿 + script + questions | **三件套成品 JSON** |

第 ⑥ 步是新增的「打包」环节：把前面几步的成果，加上沉浸模式和真相拼图需要的东西，一次性收敛成一个标准 JSON。

## 使用方法

1. 跑 ⓪ 确定「改编哪一部分、做成一关还是多关」。
2. 按 ①–⑤ 产出设计稿、本子 JSON 和 questions。
3. 把下面「主提示词」整段复制给大模型，在 `{{}}` 里填入：
   - `{{原文片段}}`：你选定的那部分原文（如不需要模型再改内容，可只给简短上下文）。
   - `{{第②步案件设计稿}}`：嫌疑人、线索、证据链、真相。
   - `{{第③④步 script 与 questions}}`：如果已经有，直接贴；没有就让它现场生成。
4. 得到的三件套 JSON 里：
   - `script` 粘贴进 `data.js` 的 `window.SCRIPTS` 数组。
   - `coach` 用于生成/维护该案的沉浸模式系统提示词（`tools/ai-coach/` 或未来按案加载）。
   - `closing` 粘贴为 `script.closing`（即直接放进 `script` 里一起进 data.js）。
5. 用 `validate.html` 检查 `script`；再人工通读 `coach` 确认不漏底、`closing` 确认可解且无误导。

> 长文本仍建议按 ⓪–⑤ 分步做，再跑 ⑥ 打包；短篇可以把 ②–⑥ 合并到一次运行，但务必让模型把「证据链」单列出来，方便你复核公平性。

## 主提示词（复制整段使用）

```
你是「谜案重启」的改编工程师。请把下面这部推理作品（的指定片段）改编成一个完整的可玩案件，并一次性输出「三件套」JSON。严格遵守下面的规则与输出格式。

【输入】
- 原著片段：
{{原文片段}}
- 案件设计稿（嫌疑人/线索/证据链/真相）：
{{第②步案件设计稿}}
- 已有的本子 JSON 和 questions（没有就留空，由你现场生成）：
{{第③④步 script 与 questions}}

【总原则】
1. 玩家只能依靠游戏内出现的线索推出真相，不能要求玩家读过原著。
2. 关键证据必须在开场或调查阶段就作为可见线索交给玩家；原著里如果直到结尾才揭示关键信息，必须【原创改编】成开场可查看的线索，保证公平。
3. 可以为了游戏性简化、合并、删减原著情节，但不得改变核心诡计、真凶和关键动机；改动处写进 script.aiNote。
4. 涉及民族、性别等时代偏见时，删去偏见性概括，保留具体历史事实；推理依据只能来自具体物证和行为。
5. 中文文案；每句台词不超过 40 字；台词里的 s 必须存在于 speakers；灰羽（guide）冷静、话少、偶尔毒舌，绝不直接说答案。

【输出格式】
只输出一个 JSON 对象，不要输出其它文字：
{
  "script": { ... },
  "coach": { ... },
  "closing": { ... }
}

三部分字段规范如下：

━━ 一、script（粘贴进 data.js）━━
{
  "id": "英文短名_01",
  "title": "作品名",
  "subtitle": "四字副标题 | 第X案",
  "source": "改编自 作者《作品名》（公有领域）",
  "difficulty": "入门 或 进阶",
  "cover": "两位数字编号",
  "aiNote": "AI 辅助拆解原著并生成台词与线索树，人工校对证据链",
  "immersive": true,
  "summary": "案件概要 100–200 字",
  "victim": "被害人（无死者则写案件性质）",
  "speakers": {
    "narr": { "name": "", "voice": null },
    "guide": { "name": "灰羽", "voice": "guide" },
    "人物编号": { "name": "人物名", "voice": "high 或 mid 或 low" }
  },
  "characters": [
    { "id": "c1", "name": "", "title": "", "motive": "", "alibi": "", "aliases": ["译名","简称","英文名"] }
  ],
  "clues": [
    { "id": "k1", "name": "6字以内", "text": "一句话" }
  ],
  "scenes": {
    "intro": [ { "s": "narr", "t": "" }, { "s": "guide", "t": "", "pose": "thinking" } ],
    "deduce": [ ... ],
    "truth": [ ... ]
  },
  "actions": [
    { "id": "a1", "type": "talk 或 search", "label": "按钮文字", "clueIds": ["k1"], "lines": [ ... ] }
  ],
  "questions": [
    {
      "id": "q1", "prompt": "", "kind": "character 或 clue",
      "choice": { "options": ["c1","c2","c3"], "answer": "c3" },
      "fill": { "sentence": "可选，带 {{0}}", "answers": [{ "text": "标准答案", "aliases": ["别名1","别名2"] }] },
      "basedOn": ["k1","k2"]
    }
  ],
  "solution": "真相一句话，80 字以内"
}
注意：嫌疑人 3–5 名且恰好 1 名真凶；线索 8–12 条（至少 4 条关键）；调查行动 7–10 个；推理题 4–6 道，覆盖凶手/手法/动机/关键细节；每条线索至少出现在一个行动的 clueIds 里；questions 的 basedOn 线索必须玩家能拿到。

━━ 二、coach（沉浸模式隐藏知识）━━
{
  "facts": ["玩家会获知的既定事实1", "玩家会获知的既定事实2"],
  "clues": [
    { "id": "k1", "surface": "玩家看到的线索信息", "meaning": "这条线索实际意味着什么" }
  ],
  "deductions": [
    { "id": "D1", "text": "可推出的中间结论", "basis": ["k1", "k6"] }
  ],
  "redHerrings": ["误导线索为什么是误导"],
  "finalTruth": "一句话完整真相（玩家拼图前不得泄露）"
}
注意：
- facts 是 AI 的权威事实库，必须写全玩家在游戏里会获知的所有既定事实：背景、人物关系、人物亲口说过的话、以及看似矛盾但最终被解释的细节。这是防止 AI 编造新事实或否认玩家已知信息的关键。
- clues 与 script.clues 一一对应，surface 是玩家可见信息，meaning 是导演层真实含义。
- deductions 写 3–6 条中间推理节点，id 依次 D1、D2…；**最终结论固定用 "C1"**。
- 每条 deduction 的 basis 只能引用 clues 的 id 或 facts 里的短语，不得引用玩家拿不到的线索。
- deductions 是灰羽判断玩家推理的依据：当玩家说对一条 deduction 时，AI 必须把它的 id 写进 `unlockedDeductionIds`，前端据此解锁真相拼图的对应空缺。
- 最终结论 C1 的文字必须与 script.solution 一致。

━━ 三、closing（真相拼图，直接作为 script.closing）━━
{
  "intro": "一句操作提示",
  "segments": [ { "text": "真相是：D 部长把信" }, { "slot": 0 }, { "text": "、重新写上地址……" } ],
  "slots": [ { "id": 0, "answer": "翻了个面" }, { "id": 1, "answer": "壁炉前" }, { "id": 2, "answer": "最显眼处" } ],
  "clues": [
    { "id": "m1", "text": "烧掉了", "initial": true },
    { "id": "m2", "text": "藏进书里", "initial": true },
    { "id": "m3", "text": "塞进坐垫", "initial": true },
    { "id": "c1", "text": "翻了个面", "requires": "D1" },
    { "id": "c2", "text": "撕成两半", "requires": "D1" },
    { "id": "c3", "text": "壁炉前", "requires": "D2" },
    { "id": "c4", "text": "警察受贿", "requires": "D2" },
    { "id": "c5", "text": "最显眼处", "requires": "D3" },
    { "id": "c6", "text": "书桌抽屉", "requires": "D3" }
  ]
}
注意：
- 空 2–4 个，答案对应“凶手/手法/关键物/地点/动机”等关键节点，答案 2–6 字；**所有空始终可以填**。
- segments 用 { "slot": 0 } 标记挖空位置，其余用 { "text": "..." }；填完后整句必须通顺且符合真相。
- `clues` 是真相拼图的线索池：
  - `initial: true` 是开局就给的迷惑线索（不能是任何空的正确答案）；
  - `requires: "Dx"` 是推理成立后才出现的线索；
  - 每个 `requires` 组 2–3 条，至少 1 条是该 deduction 对应的正确线索，其余是迷惑线索；
  - 正确线索必须出现在 `clues` 里，并挂在某条 deduction 的 `requires` 下。
- 未知线索在界面上显示为 `???`；玩家只能看到总量，不知道具体内容。

### 对话推理与线索解锁（每案必须）

- 调查给线索，对话给推理，拼图给结局：玩家把推理说给灰羽，灰羽判断后返回 `unlockedDeductionIds`；每条新推理揭示 2–3 条新线索（含正确线索）。
- 不设“联想按钮”；所有空始终可填，但正确线索一开始是隐藏的。
- 未成立的推理，对应的正确线索不出现在线索池里，显示为 `???`；迷惑线索始终存在。
- 如果玩家的推理逻辑成立、但不对应任何预设 deduction，灰羽也要正面确认，不要回答“没有效果/连不到一起”。
- 验收标准：不搜证、不和灰羽对谈，玩家只能拿到初始迷惑线索，拼不出完整真相。
```

## 落地检查清单

- `script`：`validate.html` 无红色错误；线索、行动、题目、证据链闭合。
- `coach`：`deductions` 只引用玩家能拿到的线索；`finalTruth` 不提前出现在开场或行动台词里。
- `closing`：每个空的正确答案都在 `fragments` 里；干扰块确实错误；填完后句子通顺。
