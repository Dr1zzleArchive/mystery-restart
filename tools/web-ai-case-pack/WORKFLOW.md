# 网页 AI 改编工作流（省 token 版）

目的：把「原著 → 可玩案件」的初稿交给免费网页 AI（豆包 / Kimi / DeepSeek 网页 / ChatGPT 等）完成，你只把原文片段和提示词交给它，再把结果交回 Codex 做校验、接入、测试和上线。

## 文件清单

给网页 AI 的文件（或直接粘贴内容）：

1. **原文片段**：只截取要改编的那一个短篇 / 章节，存成 `.txt` 或 `.md`。不要上传整本书。
2. **第一步提示词**：`tools/web-ai-case-pack/STEP1_DESIGN.md`
3. **第二步提示词**：`tools/web-ai-case-pack/STEP2_PACKAGE.md`
4. **格式示例**：`tools/web-ai-case-pack/EXAMPLE.json`

## 两步流程

### 第 1 步：案件设计稿（Markdown）

- 上传：原文片段 + 第一步提示词。
- 网页 AI 返回：嫌疑人、线索、调查行动、证据链、推理节点、真相。
- 你检查：嫌疑人 3–5 名；线索 8–12 条；真相能否只靠游戏内线索推出；有没有剧透。

### 第 2 步：成品 JSON

- 粘贴：第 1 步的设计稿 + 第二步提示词 + 格式示例。
- 网页 AI 返回：`{ "script": ..., "coach": ..., "closing": ... }` 的严格 JSON，外加一段自检清单。
- 你把 JSON 发回 Codex：我校验格式、修错误、接入 `data.js`、跑测试、部署。

## 注意事项

- 免费网页 AI 上下文有限：**一定只传片段**，不要传整本书。
- 版权：优先用公有领域原文；不要整段照搬现代中文译本。
- 如果输出被截断：让它「继续输出剩余 JSON」，或按 `script` / `coach` / `closing` 分三次输出。
- 不要让它改代码；它只负责内容，接入和校验由 Codex 做。
- 拿到 JSON 后，先检查有没有被包在 ```json 代码块里；有的话去掉代码块标记再发回。
