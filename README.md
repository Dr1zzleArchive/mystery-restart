# 谜案重启 | AI 文学剧本杀原型

零依赖纯前端原型，双击 `index.html` 即可运行。当前版本把文学推理作品拆成“选本子 -> 开场对白 -> 搜证问询 -> 推理作答 -> 真相揭晓”的轻量剧本杀流程，对白以视觉小说的方式逐字呈现。

> **新接手这个项目？** 先看 `FEATURES.md`（现有功能速览）和 `tools/ai-pipeline/PROMPTS_AND_GUIDELINES.md`（制作方针与提示词索引），再看下面的文件说明和 `CHANGELOG.md` 最上面几条。

## 文件说明

- `FEATURES.md`：现有全部功能的简洁总结，给接手项目的人快速了解“做到哪了”。
- `index.html`：页面结构，引入引路人面板和主舞台。
- `styles.css`：全部样式与响应式布局。
- `data.js`：剧本数据（格式 v2），包括人物、线索、逐句台词、调查行动、推理题。字段说明见 `tools/ai-pipeline/README.md`。
- `dialogue.js`：视觉小说式对白：逐字显示、对白音效、记录 / 自动 / 跳过。
- `judge.js`：困难模式填空题的模糊判定。
- `notebook.js`：右侧侦探笔记本（按案件保存、引用台词、编辑 / 标星 / 删除 / 导出）。
- `achievements.js`：成就系统（成就列表、Steam 风格弹窗与提示音、成就面板、全成就奖励）。成就列表在文件开头的 `LIST` 里。
- `mascot.js`：引路人表情差分路径与点击吐槽文案。
- `app.js`：状态机、渲染、事件处理、本地存档。
- `bgm.js`：背景音乐播放器；文件开头的 `TRACKS` 是曲目列表，`ALBUMS` 是预设专辑，新增曲目要在两处都登记。
- `CHANGELOG.md`：更新日志，每次更新在最上方追加一条。
- `ROADMAP.md`：待做功能的评估、细节与建议顺序。
- `tools/ai-pipeline/`：AI 改编流水线：第 ⓪ 步文学分析与关卡分级 + 第 ①–⑥ 步本子生成/打包提示词 + `validate.html` 本子检查工具 + `PROMPTS_AND_GUIDELINES.md`（制作方针汇总）。
- `archive/`：文学关卡素材库（作品分析报告、短 / 中 / 长篇关卡策划、总索引 `Case_Index/master_case_index.md`）。原文副本仅供内部分析，不随游戏发布。
- `assets/mascot/`：设定图与 4 个姿态的原图；`cutout/` 是网页实际使用的透明底全身像和头像；`_archive/` 存放旧版抠图与调试截图，网页不引用。
- `assets/reward/huiyu_reward.png`：全成就奖励插画（需要自行放入）。
- `assets/backgrounds/`：灰羽个人插画背景；PNG 为原图，网页实际加载同名 WebP 优化版。
- `assets/audio/`：原始音乐文件；`web/` 下是网页实际加载的压缩版 MP3。
- `scripts/prepare_mascot_assets.py`：从原图重新生成 `cutout/` 下的抠图（需要 Pillow + numpy）。

## 当前功能

- 固定剧本选择，已放入两个可完整游玩的入门案：《巴斯克维尔的猎犬》（4 名嫌疑人、9 条线索、9 个调查行动、5 道推理题）与《失窃的信》（2 名角色、8 条线索、8 个调查行动、3 道推理题）。
- 开场、调查、真相揭晓、灰羽气泡均为逐字弹出，带按角色区分音高的音效（5 种样式可选，可调音量或关闭）；可查看记录、自动播放、跳过。
- 成就系统：14 个成就（含 3 个隐藏），Steam 风格解锁弹窗与提示音，全部解锁后可查看灰羽的特别插画。
- 灰羽插画背景：设置中提供 5 张可收集插画，按“1 / 3 / 6 / 10 / 全部成就”并结合案件完成数逐步解锁；最终图要求全成就与全部已上线关卡。支持预览、切换、恢复默认背景并自动保存选择。
- 右侧侦探笔记本：随时记录线索和疑点，可引用当前台词、从线索背包一键记入，自动保存，可导出为文本。
- 两种难度：简单为选择题；困难为填空题，支持别名、整句作答和错字容错。
- 引路人“灰羽”常驻左侧，点击立绘会吐槽，不同游戏阶段会切换姿态、表情和台词；连续点击会逐级升级吐槽。
- 调查阶段可搜证和问询，线索进入背包。
- 推理阶段根据已收集线索作答，结尾显示得分、正确答案，并以对白形式揭晓真相。
- 使用 `localStorage` 保存当前进度和已破案状态。
- 右上角 ♪ 按钮打开音乐播放器：一键开关、播放/暂停、上下首、进度条、音量与静音、播放模式（列表/单曲/随机）、按氛围分类的预设专辑与自建歌单（共 8 首，默认德彪西《月光》）。

## AI 体现方式

AI 改编流水线（`tools/ai-pipeline/`）把公有领域原著分 5 步转化为可游玩的本子：提取素材、设计案件与证据链、写逐句台词、生成选择题与填空题（含别名表）、AI 复查逻辑漏洞；再由 `validate.html` 做程序检查，最后人工审核。概括为“AI 生成 → 程序校验 → 人工审核”。网页端负责把这些结构化内容变成交互体验。

尚未实现、建议下一步做的：在困难模式中加入由大模型判定的开放题，并由灰羽点评，让网页本身有一个可现场演示的 AI 功能（详见 `ROADMAP.md` 2.2 末尾）。

## 如何新增本子

按 `tools/ai-pipeline/README.md` 的 ⓪–⑥ 步骤，用 AI 把原著改编成本子 JSON（含沉浸模式和真相拼图）；用 `tools/ai-pipeline/validate.html` 检查格式和证据链；人工通读后粘贴进 `data.js` 的 `window.SCRIPTS` 数组。
